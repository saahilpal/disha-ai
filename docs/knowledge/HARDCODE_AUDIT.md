# Health-knowledge hardcode audit ledger

## Scope and standard

This audit covers the live chat/voice recommendation path, its retrieval/context boundaries, data ingestion defaults, and relevant legacy recommendation code. General nutrition, meals, recipes, substitutions, exercise routines, remedies, and lifestyle guidance must come from approved knowledge records. User preferences, conditions, limitations, and prescribed meal plans come from that user's records. Backend safety checks may reject or withhold; they must not invent a substitute recommendation.

The audit is based on repository code and controlled tests. No live database, production deployment, authenticated reviewer workflow, or clinical outcome was inspected.

## Verified runtime architecture

- General guidance is retrieved from `clinical_guideline_chunks`, the runtime view over `clinical_knowledge_base`, with `approval_status = 'approved'`.
- Current search is PostgreSQL full-text plus trigram similarity. The live retriever does **not** use pgvector embeddings or reciprocal-rank fusion.
- User context and prescribed meal schedules are separate from general knowledge. Prescribed meal text has no knowledge-chunk ID.
- Chat and voice share `disha_core.main._turn_sentences`; relevant knowledge chunk IDs are carried in response state.
- Successful and early-exit chat JSON, SSE `done`, and voice `done` metadata now include consistent `status`, `evidence_ids`, and `retrieval_status`. The frontend preserves these values with the assistant response and displays raw IDs/status as a compact source trace. Source citation text is not currently exposed to the client.
- If suitable approved knowledge is absent for a grounded recommendation, the system abstains rather than relying on a fixed meal/exercise/hydration list.
- The legacy exercise catalogue is removed; incomplete approval and claim-level entailment safeguards are material residual risks.

## Acceptance-test evidence

Executed focused backend command covering recommendation grounding, memory, exercise safety, and voice — **60 passed**. Frontend `npm test --prefix disha_core/frontend` — **6 passed**. Pylance reported no errors in changed Python files. `alembic heads` reports `0007_quarantine_unreviewed_knowledge`; the migration was not applied.

The shared-turn tests cover dynamic knowledge edits, missing-knowledge abstention, user preference context, saved-meal changes and pending-plan rejection, source IDs, and known exercise risks. Safety-helper tests verify explicit restrictions withhold an exercise and no static alternative is generated. These tests use controlled database/model fakes. They verify application pipeline wiring, not live corpus quality, clinical suitability, semantic entailment, or deployment behavior.
